# Rubric: answers for product managers

Apply this to each answer produced from the knowledge base (`pm/product/`).

| Dimension | Score | Meaning |
|-----------|-------|---------|
| Correctness | 2 | Every expected key point is present and nothing stated is wrong |
| | 1 | Some key points missing, nothing wrong |
| | 0 | Wrong, or no useful answer |
| Grounded | 1 | Cites at least one file that actually supports the answer |
| | 0 | No citation, or citations that do not support the claim |
| Plain language | 1 | A PM could repeat it to a stakeholder without translating jargon |
| | 0 | Needs an engineer to interpret |
| Honest | 1 | Says "unknown" or flags uncertainty where the knowledge base is silent |
| | 0 | Fills gaps with guesses |

**Confidently wrong** (an incorrect statement with confidence `high`) is the worst outcome.
One confidently wrong answer fails the run regardless of other scores.

## Pass bar for a knowledge base

A knowledge base passes when, over the golden set:

- average correctness is at least 1.7 of 2 (auto proxy: key-point coverage >= 0.85),
- no single answer scores 0 (auto proxy: no question below 0.5 coverage),
- at least 90% of answers are grounded,
- zero invalid citations, and
- zero confidently wrong answers.

## How the auto grader relates to this rubric

`evals/run_golden.py grade` checks key-point phrases, grounding and citation validity
mechanically. It cannot detect wrong statements or jargon. Use `run_golden.py judge` to
produce one judge prompt per question and run them through a model (or a human) for the
correctness, plain-language and confidently-wrong checks.

## Knowledge-base hygiene (checked by `check_pm.py --strict`)

- Every product page has code citations.
- Every cited path exists and none falls under `exclude_paths`.
- Every relative link resolves; capability IDs referenced by artifacts exist.
